# DevOpsHunt harness compared with Pursuit

Research date: 2026-10-22. Scope: first-party public pages and local Pursuit source; no account creation, authentication, mail, application submission or external mutation. Public-page retrieval establishes what is published, not that authenticated workflows operate correctly. Some search-tool responses were cached on different dates; displayed inventory counts are snapshots, not a reconciled live inventory.

## Finding

DevOpsHunt's published advantage is a connected job-search operation: a job corpus, approved documents, selected application queue, execution records and employer-email follow-through, accessible to the agent a candidate already uses. Pursuit has useful foundations, but its native desktop is currently a local career book and conversation runtime rather than a career execution harness. Its retained web/API system contains additional primitives that must not be attributed to the desktop. This agrees with Pursuit's existing **NOT_READY** audit. [DevOpsHunt homepage](https://www.devopshunt.com/), [Pursuit capability map](../PRODUCT_CAPABILITY_MAP.md), [functional audit](../qa/REPORT.md).

## Job data, market signals and platform boundaries

DevOpsHunt's sign-in page claims 30+ sources; the terms describe aggregation and hosted listings without enumerating source contracts. Public job pages establish a browsable corpus, not ownership of every source or permission for Pursuit to reuse it. Terms prohibit scraping/bulk extraction without written permission. Pursuit should integrate permitted primary sources rather than treat this competitor as its upstream feed. [Sign-in](https://www.devopshunt.com/dashboard/apply), [Terms](https://www.devopshunt.com/legal/terms).

The insights product publishes hiring, salary, skill and sponsorship views with methodology/denominators. The visa report distinguishes explicit current sponsorship, UK licence and US sponsor history and warns that none substitutes for individual-role eligibility. A captured date differs from an employer's posting date. This evidence vocabulary is worth adopting before copying market charts. The pages' corpus figures differ by scope/date, so no single “verified job count” is asserted here. [Insights](https://www.devopshunt.com/insights), [Visa methodology](https://www.devopshunt.com/insights/visa-sponsorship), [Trends](https://www.devopshunt.com/trends).

DevOpsHunt documents access-controlled cloud storage, TLS, purpose-based staff access, profile privacy by default, processor categories, account deletion and retained legal records. It names hosting/database, email, payments and AI categories, but the reviewed material does not specify infrastructure region, named subprocessors, at-rest encryption, per-field retention periods or audits. Its AI statement is qualified: third-party training requires a basis; it is not an unconditional no-training promise. Pursuit's local SQLite/model-choice architecture is a distinct starting point, not evidence that a future email/browser execution system is automatically private. [Data handling](https://www.devopshunt.com/legal/data-handling), [Privacy](https://www.devopshunt.com/legal/privacy), [Native store/runtime setup](../../apps/desktop/src-tauri/src/main.rs).

## Recommended build order

1. **Finish one native operation.** One permitted source and supported form family: fresh posting → jurisdiction-aware eligibility with explicit unknowns → fact-grounded packet → user-selected queue → approval bound to job, packet hash, answers and expiry → actual browser submission → independently captured receipt. Record immutable artifacts and status events locally. Treat a prefilled form or supplied confirmation string as insufficient submission proof.
2. **Make interruptions first-class.** Persist per-job checkpoints, pending user questions and blocked reasons for missing facts, unsupported form, employer login or CAPTCHA. Resume after deliberate user action; ambiguous submission enters reconciliation rather than blind retry. Test restart, stale approvals and duplicate suppression against controlled fixtures before any real submission.
3. **Close the communications loop.** Add separately granted inbox reading, original-thread reply drafts and evidence-linked status proposals. Require human review for uncertain matching or stage changes; preserve exact-message approval and ambiguous-delivery protections. A dedicated alias is an optional product decision, not a prerequisite for native Gmail.
4. **Scale only after the slice works.** Broaden sources, add actual watcher scheduling/change detection and durable worker notification delivery, then qualify additional browser/form/model/platform combinations. Evaluate an MCP interface when externally supplied clients materially help; exposing MCP alone does not supply browser execution, durable state or approval policy.

Do not copy a 100/day/all-board autonomy promise, combine the competitor's human-service and agent offerings into one claim, auto-send employer replies, or prioritize CV themes/market graphics/phone mockups ahead of execution evidence. Preserve Pursuit's local ownership and provider choice while making the operative unit an inspectable job run with documents, consent, blockers and receipts.

## Remaining verification

With a separately authorized test account: inspect the actual MCP URL and tool schemas, scope separation/revocation, CV approval/export semantics, selected-run authorization, unsupported-platform handling, CAPTCHA recovery, immutable document retrieval, submission evidence validation, inbox threading/outcome attribution and reply-send restrictions. Measure source provenance/freshness separately. Public marketing and legal text cannot establish those runtime guarantees.
