# Local diagnostics and issue reporting

Open **Help & report an issue** in the desktop utility bar. Pursuit shows a diagnostic preview before copying anything. The optional event checkbox starts unchecked. **Copy diagnostics** copies only that preview; **Open issue form** opens a fixed GitHub issue page without attaching the report. Issues are public. Review what you paste and remove personal details from your reproduction steps. Nothing uploads automatically.

The native store keeps the latest 100 allowlisted event codes and timestamps in the application-data `diagnostics/events.json` file. The report includes application version, OS and architecture. It records startup/exit, caught Rust panics, renderer exceptions/rejections, and selected engine/storage failures. Error payloads, stack traces, local paths, URLs, prompts, provider keys, resumes and application answers are never passed to this logger. Invalid or oversized event files are discarded. Unix directories/files use private permissions. Windows relies on the user's application-data directory ACLs. Use **Clear local events** to delete the retained events.

A React error boundary offers restart and diagnostics if rendering fails. A failed initial career-book read blocks editing instead of substituting an empty editable workspace. Neither path clears career data or retries external work. After a crash during a submission or message, check its saved state and employer/inbox confirmation before taking further action. Application states left during submission reopen as uncertain, with automatic retry prohibited.

Caught Rust panics are recorded without their payload when diagnostics has initialized. OS crashes, force-kill, power loss, out-of-memory termination, browser-process crashes and failures before initialization may leave no event. This is a minimal privacy-conscious error recorder, not a full OS crash dump or automatic crash telemetry service. A diagnostics initialization failure does not prevent opening an otherwise healthy career workspace; its preview reports unavailability. A dedicated upload service, retention policies for uploaded reports and operational alerting are not implemented.

Verification covers event allowlisting, bounded persistence/restart/deletion, poisoned/oversized files, default-off inclusion, fixed issue URL, render crashes, unhandled rejection categories and the startup-write guard. Browser checks use simulated Tauri IPC; Rust tests exercise the actual file store. Actual OS-webview crash/relaunch remains part of native release qualification.
