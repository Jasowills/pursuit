# Desktop-first change-impact assessment

Date: **2026-10-22**. Scope: source audit and planning for the two supplied product directives. Existing implementation is preserved. This is not a declaration that desktop/Connect features ship today.

## Decisions supplied by the user

1. All three desktop platforms are required in the first alpha: macOS, Windows and Linux.
2. After explicit setup, bounded automatic **applications** are allowed. Outreach **sending** requires approval. This supersedes the directives' blanket per-application approval language for users who explicitly enable bounded application autonomy.
3. Connect must support internet access through an optional encrypted relay without requiring a Pursuit account.
4. Support OpenCode as the agent runtime/configuration entry point and investigate OpenCode-hosted model access. Do not label an agent runtime as a model.

## Risks discovered in the audit

- Old technical docs call the OpenCode adapter “verified”; the historical proposal test does not verify streaming, interruption, tools or restart recovery. Scope that claim in the new plan.
- Current eligibility baseline treats any verified authorization as a broad positive and uses a sponsorship keyword expression that can conflate available and unavailable sponsorship. It is not sufficient authority for unattended applications. Replace/qualify these rules before execution.
- Current durable autopilot configuration is narrower than a general queue: it is not a checkpointed browser workflow with a side-effect ledger.
- Current SSE uses timestamps; Connect needs durable per-workspace sequence cursors and snapshot recovery.
- Existing approval/tool code includes boolean approval flags and environment-level runtime configuration. Future automatic authority must be evaluated and consumed by the executor, not represented by a client-supplied boolean.
- Remote/mobile state and sensitive facts must remain workspace-scoped even when hosted accounts are removed.
- “Local-first” does not imply local inference: selected hosted providers and optional Composio process disclosed data externally.

## Safe migration boundary

The first implementation changes should introduce ports/contracts and a runnable desktop/Core proof, not delete the current API or replace the landing with a fictitious desktop capture. Preserve originals, database backups and existing tests. Remove cloud/dashboard promises from public navigation when the prerelease/download experience can replace them honestly.
